# Agent 结果摘要与按需明细

日期：2026-10-26。状态：总体方向已批准；用户随后明确“需要授权的默认即可”，按推荐细化方案执行。

## 目标与已确认要求

真实双分子交互已经完成科学计算，但旧 `agent_result` 同时包含三份工具结果索引和含原始 JSON 的回答，压缩空白后仍超过前端单消息上限。本改造解决结果交付与阅读问题，不修改科学算法、预测值、证据接受规则或 Agent 模型设置。

用户已确认：采用“结果摘要 + 可展开的完整明细”，完整科学数据只交付一份，保留旧客户端兼容。界面不主动展示泛化免责声明、内部工具名、证据 ID 和技术来源说明；具体失败、缺失数据、预测分歧及影响判断的风险仍须可见。

保持 FastAPI、Jinja2、原生 JavaScript/CSS。Agent 继续使用前端配置的模型；分子生成模型不参与主聊天模型配置。

## 方案选择

1. **采用：小摘要 + 同源、所属会话受限的 HTTP 明细。** 使用现有 `/api/agent/runs/` 权限边界；明细按需获取，不占 WebSocket 帧预算。每个结果绑定不可变快照，不能读取“该 trace 的最新结果”来替代旧消息数据。
2. 单份大 WebSocket 结果：可去重，但较大任务仍可能超过单帧上限，不作为完整解决方案。
3. WebSocket 分片：可解决帧大小，但需要重组、重传与跨轮生命周期管理；已有所属会话 HTTP 边界，不增加这套机制。

现有 `ScientificPresentation` 服务用于候选引用、确认和科学授权，且随源版本变化失效，不可挪作历史结果阅读存储。本功能使用独立的展示快照，绝不赋予执行、引用或续接权限。

## 用户交互

- 默认显示简短结果和必要表格；保留数值的单位、预测属性、部分完成状态及影响判断的具体问题。
- 存在工具结果时提供一个默认收起、支持键盘操作的“查看明细”入口。
- 首次展开才读取快照；成功后在该消息内缓存。明细按工具的中文业务名称分组，展示完整公开数据、错误、质量状态及来源；内部标识仅在展开区域显示。
- 已知结果类型用表格或字段列表展示，未知结构安全地展示格式化文本；不把同一完整结果复制成多个索引。避免在结果正文直接输出大段 JSON。
- 加载失败只在明细区域显示原因及“重试”；重试是只读请求，不重新运行工具、不修改科学完成状态。
- 工作进度使用业务名称和状态，不主动输出内部步骤 ID、工具函数名或证据 ID。此范围限于本次 Agent 聊天结果及其任务面板，不重设计无关页面。
- 没有工具结果的普通回答、澄清或失败不增加空明细入口。

## 展示数据边界

新增独立展示投影模块，由服务端已验证的 `AgentResult` 和业务投影生成两个产物：

1. 有界摘要：用于 `agent_result` 与 `complete` 的正文和必要状态。
2. 规范明细：只含一份有序 `tool_result_sequence`，并保留结果状态、具体错误、warnings、接受/排除原因及必要的公开 provenance。

完整明细不包含 `tool_results` / `tool_results_by_id` 副本、不包含嵌入同一数据的原始回答字符串，不包含主模型提示、用户配置、续接快照、私密路径或凭据。服务端原有科学记录、审计文本、checkpoint 和证据账本不变。

“完整”指安全边界允许公开的全部科学字段，包括未参与排序的候选、阶段错误、失败结果与来源，而非未脱敏内部对象。新明细不得使用旧展示层的静默列表/字符串截断；先校验结构和总预算，再执行保留结构的敏感字段脱敏。脱敏事实在明细元信息中明确记录。

摘要必须在加入来源页脚和原始 JSON 之前生成，不能从已截断回答解析或用宽泛正则删除段落。比较摘要沿用既有证据接受、候选对齐、排序与排除规则，仅改变展示。现有旧回答路径仍可生成旧格式。

摘要预算按实际 UTF-8 编码字节校验，正文不超过 24 KiB，完整单帧不超过 64 KiB；前端既有 256 KiB 消息上限不变。过大的表格摘要按确定的行数收束，显示总量及明细入口，完整行仍在快照中。影响判断的错误不得被“成功摘要”覆盖。

规范明细使用现有结果级 4 MiB 总预算与 65,536 节点预算，深度明确支持 observation 的 32 层；限制适用于完整快照编码而非单个字段。超限、非有限数、循环、非法键或不支持类型均拒绝发布完整明细，不返回伪完整数据。超限时显示“结果明细超过展示容量，请缩小请求范围”，原有后台审计保留。

## 不可变快照与读取

- 复用 `workflow_artifacts` 保存快照元数据与相对路径，不创建第二份大 JSON 数据库列、不复用候选引用协议。
- 快照文件放在 Agent 数据库同级私有 `result_details/` 目录，不经静态文件路由暴露，沿用私有目录权限策略。目录属于运行时数据，不提交 Git。
- 服务端生成独立 `view_id`，规范编码的明细内容 SHA-256 作为 `revision`；revision 不参与自身摘要计算，只保存在 artifact 元数据和 HTTP 外层封装。文件以服务端生成名称写入同目录临时文件，再原子发布；登记成功后才向浏览器发布引用。
- 元数据冻结 `trace_id`、所属 `session_id`/`user_id`、格式版本、创建时间、字节数和摘要。数据库登记前在事务内检查当前 run 的双 owner；客户端不得提交快照内容或文件路径。
- 专用持久化入口写入并读取此类 artifact，限制种类、媒体类型、ID 形状及文件位置。读取前同时检查当前 run owner 和冻结 owner；路径必须等于服务端按 ID 派生的位置，并验证其解析路径仍在私有目录内。
- 读取有界字节，检查大小、摘要、schema 和版本；文件缺失、损坏、身份或 revision 不匹配时失败关闭。未授权与不存在统一 404，不泄漏路径或记录存在性。
- 新接口：`GET /api/agent/runs/{trace_id}/result-details/{view_id}?revision={revision}`。只读、同源、使用现有会话身份；响应禁用共享缓存（`Cache-Control: private, no-store`）。不接受任意远程 URL，不调用模型或科学工具。
- 同一 trace 继续运行后可以生成新快照，旧引用仍指向旧快照。展示快照无执行权限，不作为候选引用、证据重新接受或续接输入。
- 服务重启不使已保存快照失效。生命周期随所属运行数据保留，本次不增加自动清理任务；写入失败只能清理本次创建的临时/未登记文件，禁止扫描删除既有运行数据。
- 快照保存失败仍可显示有界摘要，但必须显示“计算结果已产生，明细暂不可用”；不得宣称完整结果已交付。不会回退发送超大旧帧。

## 协议兼容

- 仅 full-Web 入口在 `connection_ready.capabilities` 宣告 `result_formats: ["summary_details_v1"]`。
- 新前端只有看到能力后，才在 `chat` 和 `resume` 请求加入 `result_format: "summary_details_v1"`。不支持的新旧组合仍走现有格式。
- 展示参数在传输接收边界严格校验并剥离，存入本轮服务端 `_Turn`。不得进入工具参数、科学 request identity、requirements、冻结续接或 checkpoint。
- 缺省值是旧格式。未知格式、非法类型或在不支持的消息上设置该字段均在执行前拒绝，不能悄悄启用新行为。
- 新 `agent_result` 使用同一消息类型，并包含显式 `result_format`、有界摘要、状态以及必要的 continuation/RAG 控制元信息。明细引用只有 `view_id`、`revision`、`byte_length` 等白名单字段，路径由前端 API 层构造。
- 新帧不包含三份完整结果索引；`complete` 仍保留原来的终止与续接语义。`trace_id` 和 `client_turn_id` 关联检查保持不变。
- `_result_frame` 的 normal Pi、编译终止与编译计划路径一致使用本轮格式；包装 sender 需显式传递格式，不依赖全局设置。
- 现有候选引用/确认、科学报告、RAG 投影及其事件顺序不变。新阅读明细不产生候选确认或执行授权。

## 前端边界与生命周期

新增独立结果明细模块，API 地址集中在现有 API 层；主聊天入口仅传入已校验的引用、消息容器和摘要状态。

- 在最终正文渲染完成后挂载展开区，或通过同一消息的显式重挂载机制保留它，避免 `completeLastMessage` 重绘丢失控件。
- DOM 文本使用 `textContent`；既有 Markdown/HTML 安全处理不放松。后端字段、错误及来源都不能变成可执行 HTML。
- 每个明细实例绑定消息、trace、view、revision；异步返回只更新该实例。消息删除、重绘或断开时中止在途读取；新一轮不会把旧响应挂到新消息。
- 历史消息仍可按其固定引用重新展开；当前轮变化不把历史快照替换为新快照。刷新后的聊天恢复沿用现有范围，不另建聊天历史存储。
- 按声明字节数读取响应流；规范明细上限 4 MiB，HTTP 外层引用与 API 封装额外保留至多 64 KiB，超限即取消。JSON 类型、版本、trace/view/revision 必须匹配。不能只相信 `Content-Length`。
- 重复展开合并在途请求；重试仅重置本实例的失败读取。断网、401/404、损坏、超限等错误均可辨识且不泄漏技术路径。

## 验证与验收

实施遵循失败测试 → 最小实现 → 回归；最终必须启动项目从真实前端验收。

1. 投影契约：双分子性质/ADMET/活性结果只含一份完整有序科学数据；所有字段与已验证结果一致（除明确敏感脱敏），摘要数值、单位、排除与 partial 不变。
2. 边界：大结果、32 层合法 observation、超过预算、非有限数、非法 JSON、敏感字段与恶意 HTML；不能静默截断后声称完整。
3. 所属与不可变：异会话不可读，错误 trace/view/revision 不可读，篡改文件不可读；继续同 trace 和重启后，旧引用内容不变。
4. 兼容：无能力的新前端、无 opt-in 的旧请求、未知格式、resume、取消、等待输入、失败/部分完成、编译器与 normal Pi 路径。
5. 前端：默认折叠、点击才读取、一次加载、多次展开、重试、消息重绘、旧响应/新一轮隔离、可访问性和窄屏；现有安全渲染与续接契约保持通过。
6. 真实浏览器：运行双分子完整工具请求，确认 Agent 使用前端模型、三类工具真实执行，结果抵达且不超帧；展开检查完整端点及失败/分歧；再验证靶点查询、一次继续对话、一次页面刷新后的只读明细读取（在现有可恢复消息范围内）。截图保存在忽略的本地输出目录。
7. 执行相关 Python/Node 回归、`compileall`、`node --check` 与 `git diff --check`；未执行项明确报告。涉及运行时数据目录的变动补健康检查或说明不适用原因。

三方体验验收：用户无需阅读技术页脚与大 JSON；开发者获得独立投影/存储/控件契约；Agent 的证据、模型、工具与续接权限不因展示改造改变。

不引入新框架、依赖、科学工具、模型配置、自动清理、聊天历史存储或跨用户共享。快照不是新的科学事实来源。
