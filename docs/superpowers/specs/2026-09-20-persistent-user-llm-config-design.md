# DeepSeek 默认配置与本机持久化设计

日期：2026-09-20。基线：`20e6f44`。状态：书面规格已获用户确认，进入实施。

## 目标

主聊天模型默认使用 DeepSeek 官方接口，API Key 初始为空。用户在页面保存一次后，
同一本机、同一操作系统账号下重启应用、更新代码或切换 Git 工作树，均继续使用该配置。
不再自动沿用旧第三方接口、Gemini 模型或旧密钥。
本地分子生成工具仍使用 Ollama `gmm-llama:latest`，不随主模型切换。

“持久保存”不包含删除用户配置目录、重装系统、切换系统账号或更换电脑；这些情况需要恢复配置。
本轮不涉及多用户账号体系、云同步、模型训练、Agent 架构迁移或公网部署。

## 当前代码事实

- `src/web/app.py` 默认将 UI 配置写入当前工作目录的 `.env`，非密钥缓存写入
  `scratch/llm_runtime_config.json`；启动还会读取环境变量及该缓存。
- `src/web/llm_runtime_config.py` 已有文件锁、原子写入、单行值校验、清除密钥及公开配置脱敏。
  复用这些能力，不再引入另一套无关配置框架。
- 当前“留空密钥继续保存”只按 provider 判断复用，可能把旧端点的密钥带到新端点。
  本任务会将复用边界收紧到相同 provider 和规范化接口地址。
- `src/web/static/js/home/main.js`、`src/web/templates/index.html` 的表单默认值/提示仍偏向 Ollama，
  提示保存位置为本机 `.env`；保存后立即显示“已连接”，但保存本身并未验证远程连接。

## 方案比较与选择

1. 继续使用仓库 `.env`：改动少，但切换工作树仍会丢失配置，不满足目标。
2. 独立本机用户目录的私有配置文件：复用现有机制、跨工作树稳定，采用此方案。
3. 系统凭据管理器加独立元数据：可加强静态密钥保护，但增加平台适配；不是本轮必需范围。

用户此前选择本机明文持久保存，本轮沿用该策略；文件必须限制本机访问权限，不能进入 Git。
报告、日志、浏览器存储和公开 API 不允许包含真实密钥。密钥只由用户在表单输入，测试用合成值。

## 默认值及单一配置来源

默认 provider 为 `openai_compatible`，输出为流式，地址为
`https://api.deepseek.com/chat/completions`，模型为 `deepseek-v4-pro`，密钥为空。
官方依据：[首次调用 API](https://api-docs.deepseek.com/zh-cn/)，2026-09-20 核对。
用户仍可手动选择其他 provider、端点或模型，不锁死 DeepSeek。

默认目录：

- Windows：`%LOCALAPPDATA%/MedChat/config/`。
- Linux：`${XDG_CONFIG_HOME:-~/.config}/medchat/`。
- 其他本地系统：`~/.config/medchat/`。

UI 管理的配置以目录中的 `llm.env` 为权威来源。需要部署隔离时允许使用
`MEDCHAT_USER_CONFIG_DIR` 指向绝对、仓库之外的专用目录；拒绝相对路径和仓库内部目录。
非密钥缓存如保留也位于同一目录，不能覆盖权威配置。

加载顺序只有：有效的本机已保存配置 → 无文件时 DeepSeek 空密钥默认值。
空密钥是有效的已保存状态，不从旧环境变量中重新填入；损坏/不可读配置应明确报错，
不悄悄恢复旧密钥或回退到本地分子生成模型充当聊天模型。
项目 `.env`、`MEDCHAT_ENV_FILE`、旧 runtime JSON 和旧主模型环境变量不再是首页 UI 配置的隐式来源。
项目其他端口、科学资产、Ollama 分子生成等环境配置保持原有行为。
独立验收脚本的显式外部模型环境变量接口保持不变。

## 保存、清除与刷新

- 保存成功必须意味着权威文件已原子持久化，再更新运行中的模型。
- 保留跨进程文件锁与刷新能力，同目录的多个工作进程可读取新配置。
- 目录/文件在 POSIX 下分别限制为 0700/0600；Windows 必须检查专用目录的 owner/DACL，
  不可信时明确拒绝保存，不能宣称保存成功或自动放宽权限。
- 拒绝符号链接/reparse 路径及多行环境值；写入失败不得破坏已有配置，异常反馈不包含密钥。
- 同 provider、同规范化端点下，空白密码输入框表示保留已保存密钥；显式“清除密钥”才清除。
- 切换 provider 或端点不能借用旧密钥；未填写新 Key 时保存为空并提示未配置。
- “测试连接”只测试，不保存；也遵守相同密钥复用边界。
- 公开 API 只返回 `api_key_configured` 和固定掩码，不返回密钥片段。
- 表单重新打开时密码框保持空白，显示“已保存，无需重复填写”。“保存成功”与“连接测试成功”区分，
  保存不把连接状态伪装成已验证。

## 旧配置处理与启用

不自动复制任何旧密钥，也不扫描全部工作树收集凭据。新代码忽略旧的主模型隐式配置来源。
在本次 `main-runtime` 运行目录切换时，仅清理其旧的主模型连接字段/无密钥缓存，
保留 `.env` 中与本任务无关的端口、科学工具和资产字段；不打印字段原值、不生成含旧密钥的备份。
原始混杂工作树及其他历史副本不作批量修改。

先完成独立分支实现、回归和审查，创建 PR；遵守仓库合并授权规则，不直接修改 main。
需要生效时只重启当前本地 MedChat 服务，并核验首页及公开配置为 DeepSeek 空密钥。
不使用聊天记录中的任何旧 Key，不自动发起付费模型调用。

## 实施范围

- `src/web/llm_runtime_config.py`：默认值、本机目录解析、私有持久化/脱敏及连接身份边界。
  若路径策略需要独立文件，仅提取本任务相关职责。
- `src/web/app.py`：初始化、加载优先级、保存/测试/切换模型和跨进程刷新接线。
- `src/web/static/js/home/main.js`、`src/web/templates/index.html`：默认值、持久保存提示与真实连接状态。
- `tests/test_llm_runtime_config.py` 及必要的新聚焦测试/Node 行为测试。
- `.env.example`、README/交接文档：记录新配置来源及兼容变化；示例只含空值/占位符。

## TDD 验收标准

1. 无本机文件但存在旧 provider/URL/model/key 环境变量时，首页仍是 DeepSeek 默认、Key 为空。
2. 合成 Key 保存后，创建新 app/模拟新进程可恢复；切换两个临时工作目录仍读取相同配置文件。
3. 不写仓库 `.env` 或 `scratch`；保存后的公开 API、异常及 UI 不泄露合成 Key。
4. 留空保留、显式清除、重启后仍为空；改变端点/provider 不复用旧 Key，连接测试也不复用。
5. 文件损坏/权限拒绝/原子替换失败明确报错，原文件不被截断，不回退到旧配置。
6. 多进程写入/刷新、相对目录拒绝、symlink/reparse 拒绝及权限要求均有测试。
7. 分子生成模型保持 `gmm-llama:latest`；独立验收 CLI 的环境配置接口不变。
8. 前端初次展示、已保存提示、清除提示和“已保存≠已连接”有 Node 行为/静态回归。

实现时先运行新增测试确认失败，再最小修改至通过。运行相关 Python/Node 测试、
`node --check`、`compileall` 及现有主模型接线回归。全部测试使用临时配置目录和合成密钥，
禁止测试意外覆盖真实用户配置。真实 DeepSeek 连通性须由用户填写自己的 Key 后单独验证。
