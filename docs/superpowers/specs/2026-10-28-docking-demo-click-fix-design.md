# 分子对接示例按钮点击修复设计

## 范围

本次只修复分子对接页面“载入示例：PDE4A apo（6FG5）+ 罗氟司特”按钮的点击流程，不修改 Agent 模型配置、响应速度或对接计算后端。

## 根因

示例按钮当前通过给隐藏的蛋白质 `input[type=file]` 设置 `DataTransfer` 后派发 `change` 事件来复用上传逻辑。该事件触发的 `FileReader` 是异步的，但示例函数没有等待受体读取、解析和状态更新完成，就继续加载配体并提示成功。这样会产生竞态：在服务器较慢、浏览器较慢或 6FG5 文件较大时，文件列表、受体状态、对接盒和查看器可能仍未更新，用户会看到按钮点击无效或示例不完整。

## 方案

1. 将受体文件读取流程改为可等待的 Promise，保留普通手动上传行为。
2. 示例函数直接调用可等待的受体加载流程，完成后再设置单分子模式、填入罗氟司特 SMILES 并等待 3D 预览。
3. 统一刷新文件列表、按钮状态、查看器状态和默认对接盒，避免依赖未完成的 DOM `change` 事件。
4. 保持示例接口 `/api/docking/demo/pde4a-apo` 和真实本地 `6FG5` 文件不变；示例只预填输入，不自动提交对接任务。

## 错误处理

- 示例 PDB 下载失败时显示后端返回的安全错误，不填入半成品状态。
- 浏览器不支持 `File`/`DataTransfer` 时保留手动上传提示。
- 文件读取或 SMILES 预览失败时恢复按钮可点击状态，并显示失败提示。

## 验证

- 新增前端契约测试，先证明示例函数必须等待受体加载完成，再实现修复。
- 运行对接示例、对接结果表格和相关 JavaScript `node --check` 检查。
- 用本地页面验证点击后出现 `PDE4A_apo_6FG5.pdb`、罗氟司特 SMILES、受体/配体预览和可提交状态，且不会自动启动任务。
