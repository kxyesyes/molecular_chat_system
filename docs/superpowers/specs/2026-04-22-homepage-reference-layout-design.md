# 首页参考图高保真重构设计

日期：2026-04-22

## 目标

将首页重构为与用户参考图高度一致的首屏工作台布局，在尽量贴近其排版、层级、留白与气质的同时，保留现有首页的核心交互能力：

- 顶栏模型切换与连接状态显示
- 左侧分析工具与数据管理入口
- 首页聊天输入、发送、进入聊天态
- `RAG检索`、`智能工具`、`高级选项`
- 文件管理与帮助入口
- 现有 WebSocket 聊天主流程

本次目标不是做“相似风格”，而是将首页首屏重排成一套完整、稳定、可用、接近参考图的产品化首页。

## 设计原则

- 保留现有深色顶栏，不对其结构做重写
- 首页首屏采用“左侧导航栏 + 右侧主舞台”的双区骨架
- 右侧主舞台采用“工具层 + Hero 品牌区 + 功能卡片区 + 输入区 + 底部控制胶囊区”的清晰结构
- 主视觉重心固定为：品牌标题与输入框
- 功能卡片是次级焦点，不压过输入区
- 右上辅助入口与左上页面控制形成同一工具层，但不抢主角
- 背景以轻分子科技感为氛围，不做大面积脏重渐变
- 不改变首页现有核心业务逻辑，只重排结构并做轻量适配

## 当前问题

现有首页存在以下问题：

- 右侧首页结构仍偏旧版欢迎页，Hero 区、快捷卡、输入区之间缺少清晰的垂直层次
- 现有 3 张快捷卡过于按钮化，不具备参考图中的信息卡完成度
- 输入区虽然是主操作入口，但当前视觉权重还不够集中
- `RAG检索`、`智能工具`、`高级选项` 仍偏普通开关区，不像成品级控制模块
- 工具层、首页正文、背景装饰之间的系统感不足

## 信息架构

### 1. 顶栏

保留现有结构：

- 学校品牌
- MedChat 标识
- 模型选择
- 连接状态
- 设置按钮

这部分只允许做轻微样式衔接，不做 DOM 级重构。

### 2. 左侧导航栏

保留两段结构：

- `分析工具`
- `数据管理`

其职责不变：

- 展示各分析子功能入口
- 展示上传文档与加载示例入口

但视觉上会更规整：

- 卡片统一尺寸、圆角、阴影、图标比例
- 标题与分组间距更明确
- `NEW` 标签收敛为更精致的小标签

### 3. 右侧主舞台

右侧首页重排成以下 5 个区块：

1. 顶部工具层
2. Hero 品牌区
3. 功能卡片区
4. 输入区
5. 底部控制胶囊区

从上到下形成稳定阅读路径：

`顶部辅助 -> 品牌识别 -> 快捷进入 -> 直接输入 -> 模式控制`

## 布局方案

### 顶部工具层

位于右侧主舞台顶部，不进入全局顶栏。

左侧保留 3 个图标控制按钮：

- 收起/展开导航
- 新建对话
- 清空当前会话

右侧保留 2 个胶囊按钮：

- 文件管理
- 帮助

两组控件处于同一视觉高度，整体轻量，不压 Hero。

### Hero 品牌区

位于右侧主舞台上半部分中央，作为首页第一视觉焦点。

结构为：

- 左侧：Logo、`MedChat` 标题、副标题、简短说明
- 右侧：轻分子球背景装饰图

说明文字控制为一条简洁描述，用于强化“AI 药物设计平台”的专业定位。

背景装饰只承担氛围，不承载任何功能，不允许影响文本可读性。

### 功能卡片区

重构为 4 张横向卡片，接近参考图：

- 分析乙醇性质
- 生成类药分子
- ADMET预测
- 分子对接

每张卡片统一结构：

- 顶部圆形图标底盘
- 中部主标题
- 底部一句简短说明

卡片是首页主功能入口，不再只是旧式快捷按钮。

### 输入区

位于功能卡片区下方，作为首页的核心工作入口。

结构为：

- 宽输入框
- 右侧内嵌语音按钮
- 右侧内嵌附件按钮
- 右侧发送按钮

要求：

- 整体为大圆角工作台输入框
- 发送按钮成为输入区内最强视觉强调
- 占据明显宽度，成为第二视觉焦点

### 底部控制胶囊区

将原有的：

- `RAG检索`
- `智能工具`
- `高级选项`

从普通开关区重构为 3 枚横向胶囊模块。

每个模块包含：

- 小图标
- 主标题
- 一句更浅的说明文字

功能行为保持不变，只改变结构与表现形式。

## 尺寸比例与层级

右侧主舞台建议按以下垂直比例组织：

- 顶部工具层：约 `72px`
- Hero 品牌区：约 `240px` 到 `280px`
- 功能卡片区：约 `220px`
- 输入区：约 `88px` 到 `96px`
- 底部控制区：约 `72px`

视觉权重固定为：

`品牌标题 > 输入区 > 功能卡片 > 工具层 > 控制胶囊`

这样可以确保首页仍然首先被理解为“可立即开始工作的工作台”，而不是营销式展示页。

## 视觉风格

整体气质遵循：

- 专业
- 干净
- 留白充足
- 柔和科技感

### 颜色

- 顶栏继续使用深蓝黑底
- 主舞台使用浅色背景与极轻冷蓝灰雾感
- 重点色沿用当前系统中的紫蓝系，避免新增不协调色
- 功能卡片底色可以有轻微差异，但不做明显花哨撞色

### 圆角与阴影

- 输入区、卡片、胶囊、工具按钮共享一套柔和圆角体系
- 阴影以轻雾感为主，不允许厚重悬浮层

### 背景装饰

- 保留右侧轻分子科技图作为参考图式氛围
- 背景图需要被弱化处理，避免盖住内容
- 可叠加柔光、浅网格或轻雾层，但必须克制

## 组件行为定义

### 左侧工具按钮

- 导航切换：收起或展开左侧栏，并记住状态
- 新建对话：清空输入，隐藏聊天区，恢复首页欢迎态
- 清空会话：清空当前会话消息，保留全局设置与文件管理状态

### 右侧辅助按钮

- 文件管理：打开文件管理面板
- 帮助：打开轻量帮助面板

### 功能卡片

保留首页现有快捷动作语义，但升级为更完整的卡片入口。点击卡片后，仍然触发首页相应的预设动作或跳转逻辑。

### 输入区

保留现有逻辑：

- 输入文本
- 发送消息
- 语音/附件入口
- 进入聊天态

### 底部控制胶囊

逻辑不变：

- `RAG检索`：控制 RAG 开关
- `智能工具`：控制工具开关
- `高级选项`：打开高级参数面板

## 数据与状态适配

本次不改变核心数据模型，但需要对新 DOM 结构做轻量适配。

### 需要兼容的已有状态

- `chatMode`
- `currentMessages`
- `ragEnabled`
- `toolsEnabled`
- `sidebarCollapsed`
- `managedFiles`

### 需要适配的 DOM 引用

现有 `home/main.js` 中必须检查并按新结构同步调整以下区块的选择器：

- Hero 区容器
- 功能卡片容器
- 输入区按钮
- 底部控制胶囊区

原则是：

- 优先保留已有脚本逻辑
- 仅在新结构与旧选择器不兼容时做最小适配

## 错误处理与回退

### 结构级风险

首页当前已经存在较多历史样式和内联结构，本次重排可能导致：

- 旧样式残留覆盖新布局
- 旧脚本依赖已删除的旧 DOM
- 响应式断点下布局错位

### 处理原则

- 优先在 `index.html` 内部集中定义首页新布局样式
- 对关键结构使用明确的新类名，减少旧规则误伤
- 对 `home/main.js` 进行最小范围适配，避免继续依赖已删除的旧锚点
- 所有旧逻辑保留运行路径，不进行业务级重写

## 测试与验收

### 自动校验

至少保留并扩展首页 smoke test，覆盖：

- 关键 DOM 是否存在
- 首页核心脚本引用是否正确
- 关键交互函数是否仍存在

### 浏览器手工验收

需要验证：

1. 首页首屏布局是否整体贴近参考图
2. 左侧栏与右侧主舞台比例是否稳定
3. 4 张功能卡片是否显示完整且点击可用
4. 输入框、语音、附件、发送按钮是否正常
5. `RAG检索 / 智能工具 / 高级选项` 是否在新胶囊区中正常工作
6. 文件管理与帮助面板是否仍可打开
7. 进入聊天态后首页内容是否正确隐藏/过渡

## 实施范围

本次包括：

- 首页首屏高保真重排
- 首页 Hero 与功能卡片重做
- 输入区与底部控制胶囊重做
- 左侧导航视觉重整
- 新结构对现有首页脚本的必要适配

本次不包括：

- 顶栏业务逻辑重写
- 聊天流式消息 UI 大改
- 文件管理内部复杂业务系统
- 高级选项面板全量重做
- 其他子页面视觉统一化

## 验收标准

完成后应满足：

1. 首页首屏整体结构与参考图在布局和层级上高度接近
2. 首页仍保留现有可用功能，不因重排导致交互失效
3. 输入区成为首页主工作入口，而不是被卡片或背景抢走焦点
4. 四张功能卡片具备产品级完成度，不再只是简单按钮
5. `RAG检索 / 智能工具 / 高级选项` 以更自然的模块化方式出现
6. 页面整体气质达到“专业、干净、留白多、柔和科技感”
