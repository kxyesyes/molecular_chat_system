## 2. 已复现问题

调用链：`execute` → `assess_drug_likeness` → `_calculate_overall_assessment`，
再进入 `format_assessment`、单分子解释和简要推理。

- `_generate_interpretation` 将零Lipinski违反项解释为“预测具有良好的口服生物利用度”；
  当前工具没有调用支持这一预测的模型或实验数据。
- 调用综合评分时，Lipinski参数取的是结果字典长度而非违反项数量，现有字典长度为4。
- Veber和lead-likeness传入完整非空字典，而不是其中的布尔结果；字典整体总被视为真。

隔离环境直接调用真实工具所得证据（不是模型生成或mock）：

| 输入 | 实际规则结果 | 当前错误分项 |
|---|---|---|
| `CCO` | Lipinski违反0项、Veber符合、lead不符合 | Lipinski=0、Veber=1、lead=1；输出含生物利用度过度结论 |
| `CCCCCCCCCCCCCCCCCCCC` | Lipinski违反1项、Veber不符合、lead不符合 | Lipinski=0、Veber=1、lead=1 |

上述探针仅使用临时配置和真实RDKit，没有调用外部模型；不是完整回归结果。

## 4. 最小实现设计

### 4.1 参数传递

保持 `_calculate_overall_assessment` 的现有签名和实现公式，调用方传入：

1. 未提前舍入的RDKit QED值；
2. `lipinski_violations['violation_count']`；
3. `veber_compliance['overall_compliance']`；
4. `lead_likeness['overall_compliance']`。

现有规则分项定义保持：

- Lipinski：`max(0, 1 - violation_count / 4)`。
- Veber：符合为1.0，否则0.5。
- Lead-likeness：符合为1.0，否则0.3。
- 总分：`0.4 * QED + 0.3 * Lipinski + 0.2 * Veber + 0.1 * Lead`，最终保留3位小数。
- 原有评级分界0.8、0.6、0.4，以及所有分子描述符/规则阈值保持不变。

调用边界修复后，总分和由总分决定的评级可能发生变化，这是纠正错误，而非重新标定模型。
单项计算结果和公开数据层级保持不变，不把修复前错误总分锁定为兼容值。

### 4.2 文案与证据边界

保留真实规则通过/违反项数和QED值；去掉零违反项对应的生物利用度预测承诺。
单分子解释表述为“未违反所检查的Lipinski阈值”，而非药代、疗效或实验结论。
一个违反项、多项违反也仅说明规则筛选状态，不推导确定药代性质。

`format_assessment` 的每个分子报告说明：来源为RDKit描述符计算与启发式规则；
综合分数是既有加权规则评分，不是成药成功概率；这些结果不能确定口服生物利用度或疗效。
单分子简要推理也带相同证据边界，避免进入主模型上下文后失去限制。
批量报告中每个分子仍有来源/限制提示，批量简要推理不自称模型预测。
可以用本模块私有常量/小函数复用固定边界文字，不新增通用框架或跨领域依赖。

### 4.3 接口、错误与历史

保留success、message、data、formatted、reasoning及assessment现有键和类型；
不删除上游/适配器提供的warnings、artifacts、evidence或quality，不更改状态映射。
无效SMILES、RDKit缺失、计算异常继续失败，不借文案修复产生模拟值。
不重写历史run/checkpoint，也不改持久化schema或清缓存；修正仅影响重新执行的计算。
历史保存结果仍可能包含旧分数/旧文案，不能把本次修复描述为历史数据已全部修复。
