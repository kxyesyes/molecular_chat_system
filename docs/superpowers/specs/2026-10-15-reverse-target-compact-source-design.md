## 2. 已观察的阻塞与已有契约

- 本地 TSV 为 107,988,940 字节；Morgan 指纹有 831,120 行。
- `load_owned_source` 的 TSV 上限是 `min(32 MiB, max_snapshot_bytes / 8)`，
  默认私有快照预算为 512 MiB。真实 `initialize_strict()` 在 0.062 秒内返回
  `Invalid reverse-target owned source.`；这是首个阻塞，不是全库无效的结论。
- 前 1,000 行的当前 Morgan/MACCS 重算耗时 1.156 秒。这不是全量耗时或全量
  数组一致性验证；不能声称全库已通过，也不能假设它符合 120 秒初始化限额。
- 当前 Web 启动预载调用旧的 `get_predictor().load()`，不能给 Agent 的严格
  producer 提供来源证明，且未由严格工具拥有其关闭生命周期。
- 当前严格来源拥有私有数组、代际及路径身份；receipt 的摘要证明内容一致性，
  不单独构成认证。消费者还必须核对同一当前 producer。此边界必须保留。

## 4. 全量读入、校验与内存所有权

### 4.1 明确的资源 profile

新增服务端 `compact_v1` 获取 profile；保留旧 `initialize_strict` 的 512 MiB、
120 秒默认值及 `operation_check` 的 300 秒请求上限，旧 API/测试不自动改义。
应用组装的 Agent 严格来源选择 `compact_v1`，不允许浏览器或模型选择预算。

- 常驻快照逻辑分配上限 768 MiB；获取阶段（快照加 scratch）上限 1 GiB。
- 就绪后的每次查询 scratch 上限 128 MiB，同一 producer 最多两个活动查询；
  超额返回 busy，不排入无界队列。查询仍受现有工具 180 秒总期限约束。
- 预热默认 1,800 秒，服务端配置仅可在 120–3,600 秒内选择。
- TSV 实际读取上限 256 MiB；最多 1,000,000 行、32 列；单元格至多 8,192 个
  Unicode 字符及 32 KiB UTF-8 字节，单个逻辑记录至多 256 KiB 原始字节。
  物理行和跨行记录均增量计数，不能靠巨大单行先分配后拒绝。
- 文件读取缓冲不超过 1 MiB；NPY 头不超过现有 16 KiB；指纹处理块最多 4,096 行。
- 以上均为显式分配/输入逻辑预算，**不是操作系统 RSS 或 RDKit 原生堆的硬隔离保证**。
  记录实测峰值及限制；不通过假称 RSS 硬上限关闭门禁。

预算计入 Python 字符串、列索引、字典容量、数组、拷贝和转换 scratch；在下一次
有界分配前预留空间，完成后对账。不能只计算最终 `nbytes`。超过预算即失败，
不偷偷扩大预算或缩减语料。候选来源失败时清理异常帧，避免 Future 持有大对象。

### 4.2 表和数组的读取

1. 固定解析后的路径与本次获取代际。打开稳定文件描述符，检查普通文件身份、
   长度和所用路径；拒绝不安全链接/替换。所有句柄只属于加载所有者。
2. TSV 第一遍增量计算原始字节 SHA-256、严格 CSV/TSV 结构与逻辑记录数。
   保留 BOM、换行及带引号多行的既有兼容行为；拒绝空/重复表头、NUL、
   行宽不匹配、损坏 UTF-8，不让 pandas 修复/丢弃输入。
3. 同一描述符复位后构造私有列存储：字符串用字典编码和固定宽度行索引，
   `standard_value` 用经验证的有限非负 float64。保留全部列、原行号、字符串
   精确内容和可选身份/实验字段，不将数字样字符串推断为数字。
   第二遍原始摘要、记录数、列序及文件身份必须与第一遍一致。
4. NPY 头先验证精确 shape、dtype、维度、无对象类型与足够文件长度，再读取
   相应有界块。支持已有 C/F 内存顺序和有效 NPY 版本，不能通过换格式放宽规则。
   本地只读映射如用于 F-order 取块，须由该读入作用域独占并在退出时关闭；
   任何映射、切片或外部可变别名均不能进入发布后的来源。
5. 对**每一行**的完整 SMILES 调用现有 RDKit 指纹方法，逐元素核对 Morgan
   2,048 位和去第 0 位后的 MACCS 166 位。校验所有元素为 0/1、行顺序和
   shape。初版不以抽样、去重缓存、既有 metadata 或 ChEMBL ID 替代重算。
6. 已验证块通过 `packbits` 保存为私有 uint8：Morgan 256 字节/行、MACCS
   21 字节/行。位序固定为 big，MACCS 最后两个 padding bit 必须为零。
   验证后收紧为只读；所有权规则不因只读标志而依赖外部对象。
7. 可选 popcount 缓存按原始整数范围验证后才窄化为 uint16；缺失则从已验证
   位计算。缓存存在但错误必须失败，不能当作缺失重算并继续。
8. 全部记录、数组、计数、摘要和预算完成后，最后复核路径、获取代际和关闭
   状态，原子发布一次。任何失败、取消或超时均不得发布部分来源。

该过程允许预热较慢，不允许跳过某些分子。若真实数据中出现坏行，报告固定
错误类别并停止发布；数据修复/重建需单独说明来源，不能顺手修改用户资产。

### 4.3 逻辑摘要与 receipt 兼容

位压缩是私有内存表示，不改变科学数组的逻辑值。继续使用
`reverse-array-v1` 对逻辑未压缩 uint8 的 shape、dtype 和 C-order 字节流计算
Morgan/MACCS 摘要；在已验证块上增量计算，不构造全量解压数组。
popcount 摘要也保留既有规范。`array_codec` 描述逻辑摘要协议，不宣称物理存储。

保持 `reverse-owned-v1` 的闭合 receipt 字段、`reverse-target-record-v1` 的归一化
规则、输入/配置/结果摘要和精确原生类型。运行时 profile/进度不混入科学结果。
新旧存储表示针对相同输入的科学数组摘要必须相同；独立获取的 generation ID
仍然不同，旧结果不能绑定到新来源。不得放宽未知字段/版本接受规则。

## 5. 评分与第一名续接

紧凑评分分块解压最多 4,096 行，或使用经等价性验证的字节查表交集；保持
当前 Tanimoto、零并集、float32 存储、权重解析、阈值和物种过滤顺序。
初版优先分块解压复用既有算术，避免同时引入新的数值算法。

禁止构造全库命中记录字典列表。按原行序扫描：合并时维护每个真实 target/species
的命中数及最佳行，分数相同保留最早行；非合并时使用有界 top-k。最终排序必须
与原算法稳定排序等价。聚合表、score vectors 和记录构造均计入查询预算。
资源不足返回明确不可用，而不是返回一个被截断的“全量排名”。

现有 consumer 固定 `CONTROLS.top_k=10`，S08 请求前五名时可将已验证结果的
前五行作为明确标注的展示投影；保留完整十行 receipt，不重新排序、重新打分
或把未展示行从证据中删除。有少于五个真实命中时如实显示实际数量。

S09 仅允许引用同会话最后一个明确选定、已接受且仍可验证当前来源的排名：

- 固定原 trace、evidence、result digest、generation、row index、target/species。
- `name-sha256:*` 仅是名称/物种本地身份键，绝不能当作 UniProt accession。
- 有来源标识时按标识搜索并核对物种；只有名称时使用真实数据库/provider 的
  名称/别名和物种映射，必须唯一并保留映射来源、版本和摘要。
- 同名跨物种、多 accession、无法精确映射、过期或失败来源均要求澄清；
  不让模型选择“最像”的靶点。用户选择也必须匹配实际候选映射。
- S09 的“能否继续对接”是状态说明，不是执行授权；返回真实结构与尚缺条件，
  不创建可执行 Vina 任务，不把 PDB/配体 ID 当成已准备的口袋。

## 6. 预热生命周期与可观察性

`SourceRuntime` 状态为 idle / loading / ready / failed / closing / closed。
同一应用实例只有一个已注册 ReverseTargetTool 来源所有者及一个预热 worker。
Web startup 显式启动它；撤除旧的无所有权 legacy daemon 预载，不借用旧 singleton。
legacy 独立页面的按需加载行为不变，但不为聊天提供权威来源。

进度仅包含固定阶段、已验证行数/总行数、累计时间和脱敏 reason code；不得输出
原始分子、靶点文本、绝对路径或失败文件内容。未 READY 的查询立即明确返回
“来源正在校验/不可用”，不占据 180 秒等待预热，不自动重放用户请求。
只读状态接口和界面提示不得包含启动、取消任意共享来源或修改预算的权限。

超时/关闭先撤销发布资格并发出取消信号，再等待实际 worker 退出。每个块和
每次 RDKit 调用前后检查；原生调用不能硬抢占时，状态保持 cleanup pending，
不假装已释放，也不能启动第二个来源加载。观察期限届满可报告 unresolved，
保留真实 owner；不遗弃后台线程。模型 reader lease 不跨预热持有。

首次加载失败不自动无限重试。重试只能由显式应用重启或受控服务端生命周期
操作触发；无浏览器“修复数据库”接口。关闭、路径漂移或换代后的迟到结果不得发布。

## 7. 验证门禁与完成标准

新增聚焦测试文件：`tests/test_reverse_target_compact_source.py`、
`tests/test_reverse_target_source_runtime.py`、
`tests/agent/test_reverse_target_rank_followup.py`。先记录真实 RED，再实现：

- 紧凑/旧严格表示在不同阈值、权重、物种、重复分子、相同分数、空命中、
  合并/不合并、float32 阈值边缘下，记录和逻辑摘要逐项等价。
- 交换行、任一指纹 bit、padding、原始 popcount 溢出/负数、损坏 NPY 头、
  错行宽/NUL/BOM/多行 TSV，以及第一/二遍漂移均拒绝。
- 在预算阈值及分块边界插桩，验证未先全量分配、未全量解压、未建立命中大列表；
  查询并发有上限，加载/查询互斥与路径、取消、关闭、迟到发布规则有效。

- 第一名绑定、同名跨物种、名称键误用、歧义映射、跨会话及旧代际全部覆盖。
- 保留 `tests/test_reverse_target_invocation_receipts.py`、popcount、数据质量、
