# 靶点结构与分子分析复合工作流设计

## 目标

让用户在一次前端请求中安全完成“明确 SMILES 的分子性质/ADMET + 明确靶点的结构检索”，保留每个工具的真实结果与失败状态，不让 Agent 模型删减科学义务，也不把对接执行或分子生成混入该工作流。

## 当前问题

现有 Web admission 将包含靶点结构检索的请求路由到 `target_database_search`，该工作流只允许靶点库工具；当同一请求还包含性质或 ADMET 时，入口直接返回澄清/拒绝，已提供的明确分子结构也不会被计算。完全放开通用模型会重新引入“模型自行忽略某个科学义务”的风险。

## 方案

新增服务器确定性的 `target_structure_molecule_analysis` 工作流，工具白名单固定为：

- `target_database_search`
- `property_calculator`
- `admet_predictor`

入口只在以下条件同时满足时选择该工作流：

1. 请求包含靶点结构检索意图，并且不是运行对接、生成分子或反向寻靶。
2. 请求包含分子性质或 ADMET 意图。
3. 请求包含恰好一组可由 RDKit 验证的明确 SMILES。
4. 请求中的靶点标识可解析为一个明确靶点；多个靶点、模糊靶点或仅有自然语言分子名称继续澄清，不猜测。

## 执行顺序与绑定

服务器生成三个固定步骤：

1. `target_database_search`：使用解析后的单一靶点文本，保留结构记录、实验/AlphaFold 状态和推荐结构。
2. `property_calculator`：使用同一组用户 SMILES，不从靶点结果或模型文本借用结构。
3. `admet_predictor`：使用同一组用户 SMILES；ADMET 不可用时保留性质和靶点结果，状态为部分完成并显示可操作原因。

步骤输入、工具顺序、允许工具和输出键全部由服务器计划生成；模型只负责普通 Agent 对话，不负责重写该复合科学计划。

## 失败与安全边界

- 任一工具失败不得伪造数值或把部分结果标记为全部完成。
- 结构解析失败、多个 SMILES、多个靶点或缺少 SMILES 时不启动科学工具，返回明确澄清。
- 出现“运行/执行/开始对接”时继续走现有对接授权路径，不进入本工作流。
- 出现正向分子生成、候选排序或反向寻靶义务时不进入本工作流，避免遗漏其他科学任务。
- “推荐适合后续对接”只作为结构检索的注释，不代表已经运行对接或确认口袋。

## 结果展示

复用现有结构化展示：靶点检索表、分子性质表和 ADMET 结果块按工具顺序呈现。成功工具的结果即使后续工具失败也保留；失败原因放入步骤/明细，不覆盖已经验证的科学结果。

## 验证标准

- 单元/契约测试：复合工作流只生成上述三个工具，输入绑定和禁止工具边界稳定。
- 入口测试：普通单工具请求、对接执行请求、生成请求、多个靶点和缺失 SMILES 不被误路由。
- 真实前端测试：使用项目 `MedChat` 环境启动服务，提交“CCO 的性质和 ADMET + PDE4A 结构检索”，页面显示三个真实步骤及结构化结果；再验证一个 ADMET 失败场景仍保留性质与结构检索结果。
