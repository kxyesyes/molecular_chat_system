# 精确 PDB 检索与 6SAM 真实对接验收设计

日期：2026-10-17。工作分支：`codex/browser-agent-real-acceptance`；沿用 Draft PR #209。

## 1. 授权、目标及设计评审点

维护者已授权补充精确 PDB 检索、以 6SAM 继续核验，并授权 Agent 在浏览器中
完成当前输入的一次性确认以及真实 Vina、构象和下载核对。设计文档仍待维护者
评审；该评审点不要求再次授权浏览器操作，也不制造任何运行时审批凭据。

成功条件是当前普通首页中的权威检索真正返回 6SAM，随后同 owner/source/task
完成显式科学选择、输入预览、参数确认、READY 一次性确认、真实执行和下载比对。
直接调用诊断函数、历史检查、文件名或来源摘要都不能替代这条链路。

## 2. 已核实事实及不能预设的结论

- 现有 RCSB 搜索按 accession 返回有限条目，默认最多十个。现有工具未将
  明确 PDB 标识传入权威检索；本地命中或一般结构缓存亦可能提前返回。
- 现有 `RcsbClient` 已有有界 JSON 客户端、同一操作 deadline、polymer entity
  检索、GraphQL 条目详情和实际 accession/entity 归一化；优先复用。
- [6SAM 官方条目](https://www.rcsb.org/structure/6SAM)记录人源 BCHE/P06276、
  X 射线结构、2.50 Å、构建体突变及 L3H Subject of Investigation。
  条目关联的论文摘要描述该复合物的非共价抑制机制；这不是对阿司匹林的实验结论。
- 6SAM 的科学适用性仍须当前原始 PDB/mmCIF/CCD 比对、完整原子和连接、
  参考配体资格、缺失/突变限制及受体准备验证决定，不建立编号白名单。

## 3. 方案比较与选择

**A：在既有目标检索链路增加可选精确 PDB 约束（推荐）。** 工具提取明确标识，
service/resolver 将约束传给既有 RCSB 搜索与归一化。普通查询不变，指定结构的
查询既有来源链路可审计，新增范围是解析、查询、缓存隔离和回归。

**B：扩大普通结果列表再筛选。** 可复用列表路径，但受列表上限、分页顺序、
网络预算和历史缓存影响，不足以保证指定编号已被查询。

**C：新建独立 PDB 工具或手工注入结构来源。** 新工具增加路由与来源凭据契约；
手工注入不能满足当前同会话权威来源门禁。本次不采用。

## 4. 方案 A 的精确契约

### 输入与兼容性

- 沿用现有 `target_database_search` 工具名称及结果形状。现有无 PDB 约束调用
  的参数、一般检索、缓存、AlphaFold 回退和排序保持不变。
- 支持在明确目标/UniProt 查询中使用单个带标签的四字符 PDB 标识（例如
  `PDB: 6SAM`），以及工具结构化输入的可选 `pdb_id`。大小写可规范化，但
  不截断前缀、不接受路径/URL、不从任意正文单词猜编号。
- 多个冲突编号、无效标识、否定或歧义请求明确拒绝或要求澄清，不能悄悄丢掉
  PDB 约束继续普通查询。本增量不实现只有 PDB 编号时的任意目标反向发现。

### 权威检索与来源

- service 的可选精确约束贯穿 resolver 和 RCSB client；指定 PDB 时不允许
  本地一般命中或默认十条结果代替该查询。
- RCSB 查询同时约束 UniProt 和条目编号，仍返回实际 polymer entity 命中，
  再经既有 GraphQL 详情、实验类型、实体、UniProt 和物种核验。
- 对不匹配条目/实体、错误物种、重复或缺失详情、未知方法和上游失败保持拒绝；
  无命中不替换成另一个条目或 AlphaFold 模型。网络失败与真正无匹配严格区分。
- 复用有界客户端及原 deadline，不增加开放 URL、无限分页或额外模型权限。

### 缓存、当前会话与权限

- 精确结果须与一般 accession 结构集合使用不同缓存键，键绑定 accession、
  organism 和精确 PDB；任何精确缓存命中仍核对请求编号与实际结构身份。
  不把单条 6SAM 写成该靶点的完整一般结构集合；不污染默认十条缓存。
- 来源证据/新鲜度和 target/structure 规范化沿用现有字段；只能由实际工具结果
  进入当前会话的 accepted source，不能使用诊断输出、模型文本或旧 PR 台账补造。
- 不更改 C 审批、来源归属、nonce、Origin、预算、物理清理、一次性执行和下载授权。

## 5. 文件边界

- `src/agent/tools/target_database_tool.py`：明确 PDB 约束的提取、拒绝与传递。
- `src/target_search/remote_clients.py`：精确 RCSB 条件、实际返回编号核验。
- `src/target_search/authoritative_resolver.py`：可选约束传递及显式无匹配语义。
- `src/target_search/service.py`：本地/一般缓存旁路、精确缓存隔离及结果规范化。
- `tests/test_target_pdb_exact.py`（新增）：独立正反契约和缓存/来源集成测试。
- 既有 `tests/test_target_search.py`、`tests/test_target_search_fallback.py`、
  `tests/agent/test_web_docking_sources.py`：按实际受影响范围选择回归，不重复无关套件。
- 设计批准后增加具体实施计划，更新 `docs/handoff/latest.md` 及现有 S10 validation。

不在本阶段修改对接评分方法、受体/配体化学规则、全局模型或前端架构。真实验收
发现的新缺陷须先定位和建立失败测试，不临时放宽门禁。

## 6. 实施与验证次序

1. 先建立失败测试：有效精确查询、无效/冲突/否定输入、上游错误/错实体/错物种、
   精确缓存不受普通列表遮蔽且不污染普通缓存、工具结果进入实际来源凭据。
2. 最小实现后运行聚焦测试、受影响回归、compileall、diff 与不泄露内容的提交检查；
   独立审查当前增量。没有 JS 修改则不重跑无关 Node 套件。
3. 当前服务加载新代码后，只等待其真实预热完成，不沿用另一进程的 READY。
4. 在普通首页明确查询人源 P06276 / PDB 6SAM，再以阿司匹林进入同会话对接。
5. 依据完整来源选择蛋白、L3H 参考、各异源残基去留、实际构象和全部适用限制；
   不补原子、不忽略共价/修饰连接、不默认勾选未知科学决定。无合法投影则说明原因。
6. 审核来源摘要、派生受体/配体、计算配体 provenance、口袋规则/坐标、参数，
   再在用户已授权下点击当前 READY 的确认，不构造后台审批请求替代页面操作。
7. 核对真实 Vina 版本/退出状态/原始输出，逐项比对页面最佳能量、单位、构象数；
   检查构象字节摘要、结构完整性及可视化；通过页面下载并核对实际文件摘要和内容。
   不将合成测试、预测值或预览当作实验结合结论。
8. 记录实际命令、成功与失败、未执行项、文件、commit/PR；保持 Draft，不擅自合并。

## 7. 自审

本设计没有待填参数或隐含实现开关。普通查询兼容与精确查询隔离一致；科学选择
和运行时授权分离；官方条目与后续验收证据分离。验收中无法满足的条件必须保留
失败信息，不通过扩大预算、来源白名单或修改历史输入来达标。
