# MedChat 逐轮模型决策 Agent：渐进迁移设计

日期：2026-09-08。状态：方案 1 已获用户选择；本文待用户审阅，尚未实施。
代码基线：`d1aac20`。设计分支：`codex/model-driven-agent-design`。

## 1. 目标与判定方式

目标不是删除带有 workflow 字样的文件，而是取消固定科研步骤对聊天任务决策的接管：
模型在每轮读取真实观察，决定下一工具、补充信息请求或结束；Harness 执行权限、输入、科学证据和预算约束。
同一请求遇到不同观察应能产生不同的后续行动，并有事件和结构化记录证明。

保留工具内部确定性计算、任务队列、恢复、取消和审批。它们可以继续使用工作流机制，但不能替主模型预先写死科研行动顺序。LangGraph 图的控制骨架不等同于固定科研流水线。

这细化了 [工业级平台设计](2026-08-10-industrial-agent-platform-design.md) 中的自主规划目标；
不重做 Temporal、OpenSandbox、模型训练、前端框架或身份系统。

## 2. 已核实的现状

| 现有文件 | 事实与迁移含义 |

| `src/agent/planning/task_planner.py` | TaskPlanner 根据任务类型生成确定性步骤；应退出新 Agent 默认路径 |

| `src/web/chat_handler.py` | 须保留事件和结果兼容，但新路径不能先由 should_use_tools/静态 Router 拦截所有意图 |

复用现有 StateGraph API，不在本任务升级依赖族或引入第二个 Agent 框架。
前轮结构核查运行五个规划/执行/Harness/路由测试文件：403 passed；这是契约测试，不是外部模型自主能力验收。

## 3. 决策与执行的分工

采用一个模型决策循环，最小控制状态为：

```text
用户请求 → 输入/权限预检 → 模型决策
                           ├─ tool → 校验/执行/证据登记 → 模型决策
                           ├─ clarify → 等待用户补充
                           └─ finish → 证据化呈现与终结
任何节点：取消/预算耗尽/不可恢复错误 → 诚实的终态
```

- 模型负责理解目标、选择允许的能力、解释取舍、根据失败/空结果改变策略。
- Harness 负责真实执行、参数与来源绑定、访问控制、预算、结果校验、恢复和最终状态。模型不能自行授予权限、声明工具成功或修改观测值。
- 普通聊天也可由主模型直接 finish，不应返回硬编码欢迎语或调用科研工具。
- 本地 `gmm-llama:latest` 仍是候选生成模型；主模型不能通过自编 SMILES 绕过该工具完成生成任务。
- 首版每轮最多执行一个工具，避免并行调用与局部失败处理使语义复杂化。批量候选通过已有结构化工具能力处理。

## 4. 结构化协议与模型适配

在现有 contracts 下增加带版本的决策契约，Pydantic 严格校验，拒绝额外字段和类型自动猜测：

- `tool`：规范工具名、受限输入或已有 observation/candidate/artifact 引用、简短公开目的。
- `clarify`：缺失字段列表、给用户的具体问题。不能擅自修复用户的无效结构。
- `finish`：回应类型（普通解释/科研结果）、证据引用和有界说明；不能接受模型提交的任意科学数值作为结果。

记录模型名、provider、decision_id、轮次、耗时、usage（上游提供时）、finish_reason 与已选择动作；不存储私有思维链。简短动作目的不是完整推理过程。

给现有主模型适配器增加独立的结构化决策方法，保留原 generate/stream_generate 的聊天兼容。
首选显式配置的原生结构化工具调用；不支持时可显式选择严格 JSON 决策模式，两者归一到同一契约。
不将任意正文正则匹配为工具命令，不通过字符串“模型调用失败”判断成功，不接受截断 JSON、多个冲突动作或不完整 tool call。
工具调用响应要保留调用 ID；下一轮消息包含与之对应的已校验观察，不能只发送用户原始 query。

不支持决策协议、凭据缺失、401/403、协议错误应返回明确模型不可用/失败，不能悄悄执行旧 Planner。
可修正的 schema 错误允许一次有界纠正；只返回公开 schema 错误，不转发敏感响应或堆栈。
每次网络重试和协议纠正均计入轮次与请求预算。

## 5. 工具目录、输入来源与保护

由现有 ToolRegistry/ToolSpec 提供允许工具及结构化描述，不另维护一份命名和 schema 清单。
新路径的工具可用性由请求权限、enable_rag/enable_tools、部署能力和审批决定，不由某个固定 skill 的预设步骤决定。
Router 可作为非权威提示留存；不能在新路径中决定整张计划或越过用户“不要调用工具”的限制。

工具网关沿用现有兼容适配与 AgentResultValidator，再写入 EvidenceLedger。不得直接调用裸 tool.execute 绕过结果校验。
需要从旧 session 提取公共单步执行服务时，同时迁移旧调用方，避免复制两套超时/验证/持久化逻辑。
不能仅因挂着 adapter 名称就认为 artifacts/evidence 已完整保留；必须补字段逐项回归测试。

下游输入优先引用当前 trace 内的结构化产物，由服务端解析：

- generated candidate IDs → properties/ADMET/activity，禁止混入模型新编候选；
- reverse-target evidence → structure search，禁止用原始 query 假装消费上游；
- docking 只使用授权的真实文件引用与完整 box，路径必须在允许范围内；
- 用户输入的 SMILES 与工具生成的 SMILES 保留不同来源，不把解释中的例子变为计算对象。

初始输入来自用户/可信会话资产；模型不能借“修正参数”替换无效分子。跨 trace/用户引用、路径遍历、未知工具与缺必要字段均拒绝。
工具文本、RAG 文档和数据库结果都是数据而非新指令；返回的“忽略限制”不能扩大权限。
已有外部下载、对接、模型训练和写入审批边界继续有效，不因自主模式开放任意网络、shell 或文件操作。
在审批衔接未验收的阶段，受限动作只请求授权，不先执行后补审批。

## 6. 证据化输出

沿用 ToolResult、ScientificClaim、EvidenceLedger 和现有前端结果契约，不再创建另一套科学报告格式。

模型可选择展示哪些已验证结果及提出下一步建议，但科学值由服务端从工具观察中生成 claim 并渲染：

- claim 不仅需要存在的 evidence ID，还必须绑定该观察中的字段、值、单位和候选 ID；
- pIC50、binding energy、ADMET 状态、候选数量和实验/文献来源都不能由模型自由填写；
- 任意含未引用科学数值或声称未执行计算已完成的科研正文不得直接发给前端；
- 首版科学摘要使用受控状态/结果块，开放文本仅承载非数值的解释和明确标为建议的内容；无法可靠校验的自由科研结论不渲染；
- 普通知识解释可自然语言回答，但不能冒充已检索文献、实际计算或实验发现；
- 规则判断应标为规则结果，不能被升级成训练模型预测；demo/fallback 不满足真实模型的通过条件；
- 工具失败、不可用、候选不足和不确定性必须保留，不因模型选择 finish 变为 passed。

用户请求义务（例如数量、禁止 docking、必要性质项）在开始时形成受校验的任务要求，不能由后续模型静默放宽。
最终 passed 要求请求义务都有对应证据或被用户明确修改；部分完成为 partial，无有效成果且未完成为 failed/rejected。
这约束结果是否完成，不规定固定工具顺序。

## 7. 生命周期、预算与恢复

StateGraph 负责决策循环的控制；现有 AgentStateStore 继续作为唯一权威持久化来源。
本阶段不增加并行的 LangGraph checkpoint 数据库。

建议首版默认硬边界：16 次模型请求（含重试）、12 次工具尝试（含重试）、300 秒前台任务总时长。
单次模型请求不超过既有 60 秒预算，工具沿用各自 ToolSpec 和运行时上限。
长任务交给既有任务设施；不能因为转后台就清零预算或重复提交。
这些是可配置资源上限，不是科研流程步骤。模型 token 使用已知时记真实 usage，未知时标 unavailable；
没有 provider 价格表不能声称精确金额预算已实现，首版以调用/token/时间上限控制费用风险。

相同工具、规范化参数和模型/工具版本的成功结果在同任务内优先复用；没有新观察时重复请求不再次执行。
显式独立重复实验必须有不同 repetition_id/允许预算，不能被去重掉，也不能由模型随意改变 ID 绕过限制。
不可重试失败不盲重试；模型可以基于失败请求补充或选择已获授权的其他能力。
重试策略只由一层执行，防止模型循环和 adapter 重试相乘。

记录 prepare/dispatch/observed 状态、调用身份、输入摘要、版本、校验后的输出/错误、warnings、artifacts。
已确认结果可恢复；dispatch 后崩溃或 timeout 且工具可能仍在运行，应先按真实 job ID 核查。
无法确认结果的非幂等动作不得自动重放，不承诺跨外部副作用的 exactly-once。
无可靠运行引用时输出明确“执行状态待确认”，而不是模型猜成功/失败后重做。
取消后不再派发新动作；同步线程未实际停止不能被呈现为计算已停止。
恢复时继续使用原授权快照和预算；授权已撤销、引用失效或模型/工具版本不兼容时须重新校验，不能挪用另一状态库的记录。

Web 端保持现有事件名与终结包兼容；每轮 planning 事件附轮次与 decision_id，工具事件附对应调用 ID。
工具流尚未结束时显示不定进度，不按未知总步骤伪造 100%。
clarify 必须结束当前发送的等待动画并保存待补充状态；用户回复经校验后才恢复，不自动跳过缺参数。
每个请求只发送一个终结响应，事件/恢复重放须可去重。

## 8. 分阶段交付与退出条件

### A：最小可用自主闭环（首先实施）

范围：模型结构化协议、单一动态 StateGraph、复用工具网关、证据输出、预算/取消/基础恢复、ChatHandler 接入。
先开放性质、类药性、活性、靶点搜索和普通聊天；其余能力必须明确显示本阶段不可用，不暗中转旧科研流程。
测试必须证明新路径不调用 TaskPlanner.plan，即使旧 planner 被测试替身设置为抛错也可完成。
性质和活性用真实 RDKit/隔离权重验收，靶点查询有记录/无记录两种观察必须可追踪。
这个阶段通过不等于整个 Agent 迁移完成，也不自动切换生产。

### B：其余科研任务迁入同一循环

在 A 的同一循环中扩展生成、ADMET、RAG、反向寻靶、筛选和既有 docking 作业接口。
不新增第二个 coordinator，不新写固定“设计 6 步”作为主入口。
验收候选不足、无效候选、无真实活性模型、空靶点数据库、缺 receptor/box 与长任务取消/恢复。
仅在具备可信来源/授权时自动补查；不能制造结构、数据集、模型或结合能。

### C：切默认并清理旧流程

新旧控制模式互斥，部署配置选择明确、每次运行记录实际 backend；新模式失败不自动落旧模式。
保留现有 AGENT_HARNESS_MODE 的旧执行语义，新控制模式配置与它的非法组合须报错，不能被 Factory 当未知值默默回退。
A/B 全部验收通过并得到上线授权后，默认聊天入口切动态 Agent；旧模式只允许显式运维回滚，不接管同一个已执行任务。
之后按引用与回归测试逐批移除无调用者的固定模板和旧路由决策路径；保留仍由 API/后台任务使用的公开兼容接口。
最终删除旧模式配置前先完成消费者迁移与回滚发布安排。仅把类名改成 Agent 不算完成。

每阶段一个范围明确的实现提交/PR；不把当前基线继承的历史提交直接做成巨型 main PR。

## 9. 验收矩阵

| 类别 | 必须证明的行为 |
|---|---|
| 主模型真实参与 | 每轮均有真实 provider/model/耗时与响应状态；并非固定文本或只首次路由调用 |
| 观察驱动分支 | 相同请求分别遇到有记录/空结果/不可用，下一动作合法且与观察一致，不仅改变解释文字 |
| 自主停止与补充 | 不必要的下游计算不执行；输入不完整时 clarify，补充后能继续 |
| 普通聊天 | “你好/解释概念”调用主模型，不误触发生成或计算 |
| 真实数据流 | 记录和断言下游消费的 candidate/evidence/artifact ID，拒绝伪造/跨任务引用 |
| 科学真实性 | 无效 SMILES 不产性质；未运行 Vina 无能量；模型缺失不返回模拟 pIC50 |
| 反注入与权限 | 用户或检索内容要求越权工具/路径/关闭校验，工具未执行 |
| 预算与协议 | 重复动作、截断 JSON、多动作、provider timeout、循环上限均有有限终态 |
| 恢复与幂等 | 成功动作不重复；状态不明的副作用不自动重放；错误、artifacts 与版本不丢失 |
| 前端 | 能看到实际动作与终结；clarify/failed/partial 不转圈、不假装 100% 成功 |

先用受控模型/工具替身做分支与故障契约测试，明确标为测试替身，不能计作真实科研通过。
再运行真实外部模型 + 真实工具案例，每个案例至少 3 轮重复，记录 pass/partial/failed、p50/p95、动作分支和失败类型。
不要求所有合法工具顺序逐字一致；评估目标、依赖、证据与边界是否满足。
真实依赖缺失必须 partial/failed/skipped，不能因契约通过宣布自主能力通过。

优先复用 `scripts/run_agent_acceptance.py`、`src/agent/evaluation/`、`data/agent_evals/`，
新增控制模式标签与观察驱动评测维度，不另起验收框架。
真实 API key 仅来自运行时环境变量或本机密钥管理器，不输出、落盘或提交。测试日志不保存私密思维链、原始密钥或敏感用户文本。

## 10. 文件复用与拆分原则

- 模型协议：扩展 `src/agent/openai_compatible_model.py` 与 `src/agent/contracts/`；保留原聊天接口。
- 动态控制：`src/agent/harness/` 下单一实现，复用现有 LangGraph 依赖与工厂边界。
- 原子执行：从 `runtime/run_session.py`、`orchestrators/workflow.py` 的既有逻辑提取共享职责；旧入口同时调用该职责。
- 权限/科学校验/证据：复用 `tooling/`、`validators/`、`evidence/`，不复制一套宽松的 Agent 专用版本。
- 持久化/事件：扩展现有存储协议与 event bus，schema 变更须向后兼容并补恢复测试。
- Web：修改 Supervisor/ChatHandler 接线与必要状态显示，复用现有前端卡片和安全渲染。

未正式实施前不写死尚未创建的文件名。以单一职责、小模块和明确契约控制复杂度，避免继续将所有功能堆入 Supervisor。
