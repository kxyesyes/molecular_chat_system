# 首页对话中的多配体对接

## 用户任务

在同一条首页对话里，把多个配体与同一个实验受体的同一个口袋对接。例如“把 CCO 和 CCN 分别与 PDB 6SAM 对接”，或在已有候选卡片和受体检索记录时说“把候选 3 和 1 都与刚才的受体对接”。浏览器中的确认、执行状态和构象下载都在这条对话内完成。

## 输入与确认

- 对显式 SMILES 列表逐项解析和验证，保留输入顺序及立体化学。对候选序号，从当前会话已确认的展示记录读取结构，保存原候选编号并按用户点名顺序列出。候选 3 排在第一行时，仍标为“候选 3”。
- 受体沿用首页现有的实验结构身份核验、链和参考残基选择。若本次缺少受体、某个序号越界或配体无法解析，指出具体缺项或行号，给用户机会修正整张清单。批量数量遵循部署已有的配体上限。
- 受体和口袋只准备一次。确认单同时列出全部配体及其 SMILES、受体、参考残基、盒参数和每个配体的构象上限。一次明确确认授权这一张清单；修改任一输入使先前确认失效。确认前可以取消，此时执行任务数为零。

## 执行和结果

首页保留现有对接启用策略、同会话授权和已核验的输入。专页批量路由目前接收上传文件，在所有配体结束后写入终态记录。首页需要先为整批建立唯一的执行记录，再调度各项；从现有批量队列复用有界并发、取消和有序汇总逻辑，首页各项继续通过已核验的受体、配体和工具策略执行。每一项的构象都通过服务端按会话授权的下载入口交付。

结果表按确认单顺序显示原编号、配体、状态、最佳 Vina 预测评分及构象数。某项运行失败时，该行显示原因，已有成功行保留结果和下载链接；整批显示成功数、失败数和部分完成状态。重复点击和刷新均只读取或复用原批次。单配体请求继续走现有流程。

## 验收

1. 在真实首页用两个显式配体和一个已核验的受体完成 Vina 对接。确认前核对执行任务数为零；连续点击确认后，核对只有一个批次，每个配体各执行一次。
2. 从同会话真实候选中按逆序选择两个，逐行对照原展示记录、确认单和实际执行输入。在结果页下载两份构象，用各自文件的摘要、构象数和评分核对对应行。其他浏览器会话不能读取这些构象。
3. 分别覆盖越界序号、无效 SMILES、取消和刷新。用可控的逐项执行失败补充回归，验证成功行仍可读回、失败行不带分数，整批状态准确。报告区分真实 Vina 验收与注入失败的回归。
4. 复跑首页单配体确认与下载、专页批量队列和会话隔离测试。已有单配体和批量历史记录沿用各自的读取入口。
