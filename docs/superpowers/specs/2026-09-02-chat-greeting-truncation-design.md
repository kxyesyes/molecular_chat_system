# 普通聊天模型调用与截断可见性设计

## 目标

修复普通问候绕过外部主模型、普通聊天误显示 Agent 工作流面板，以及外部模型回答因复用本地 Ollama 的 600-token 限制而被截断且用户不可知的问题。

## 设计

- 所有非空用户消息进入同一 `_process_message()` 链路。问候语属于普通聊天，不再由后端静态文案提前返回；Router 仍负责决定是否调用科研工具。
- 前端发送消息时不预创建 Agent 面板。仅在收到首个 `agent_event` 时创建并重置面板，因此普通聊天、问候语和概念问答不会出现假的“执行中”。
- 保留 `inference.max_tokens` 作为本地模型预算，新增 `inference.external_max_tokens` 作为 OpenAI-compatible 外部模型预算。模型具有外部 provider 标识时使用后者，默认 4096。
- 流式或非流式响应结束后读取模型适配器的安全元数据。若 `finish_reason == "length"`，最终内容追加明确提示，并在 `complete` 消息中携带 `finish_reason` 与 `truncated: true`；不自动续写，避免重复内容和额外计费。
- 普通知识问答提示词要求直接回答当前问题，默认保持精炼，不输出整套平台宣传清单；科研数值仍必须来自真实工具。

## 错误与兼容性

- 不改变 Agent 事件、科学工具结果或分子生成模型配置。
- 不记录 API key；只消费模型适配器已有的 `finish_reason`、模型名等非敏感元数据。
- 旧前端仍可忽略新增的 `finish_reason` 和 `truncated` 字段；现有 `content` 字段保持不变。

## 验收

- “你好”调用主模型一次，不调用 RAG 或科研工具，并以完整消息结束。
- “什么是药物分子设计”使用外部模型预算 4096，而本地模型仍使用 600。
- `finish_reason=length` 时响应包含截断提示和结构化标记。
- 普通消息发送时不创建 Agent 面板；收到 `task_started` 后才创建并清空面板。
