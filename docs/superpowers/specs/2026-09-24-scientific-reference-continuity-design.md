# T09：科研对象跨轮引用与有界恢复

## 状态与范围

用户选择方案 A：同一浏览器会话刷新、断线或服务重启后可恢复候选引用，默认有效期 24 小时。用户随后明确确认本书面设计；现进入第一增量“契约与原子存储”实施。具体证据见同日实施计划，不代表 T09 全部完成。

基线 main `9f065b3`；设计分支 `codex/scientific-reference-continuity`。遵守任务书第14节，不切换生产 Agent/实验决策入口，不启用模型，不自动迁移生产数据库，不引入 Redis、向量记忆库或新执行器。

## 当前证据

- `src/web/chat_handler.py` 仅将当前 query、工具开关和服务端 session_id 等传给 Supervisor，没有权威的上一轮候选引用。
- `CandidateSet@1` 是科学输出 schema；其中 version=1 不是候选集合修订号。candidate_id 也不是跨集合全局主键。
- `src/web/static/js/home/molecule_candidates.js` 按 ID/SMILES 跨事件去重，存在容量上限和歧义 trace 拒绝；main.js 按实际 payload 渲染卡片。这些行为必须保留，不能把工具原始数组下标等同于用户所见顺序。
- `SQLiteAgentStateStore` 已持久化 run/checkpoint 和归属；普通 metadata 更新不提供科研对象的归属/修订校验。已有 decision_continuation 是等待中的决策续接协议，不是新一轮科研对象引用。
- `AgentSessionMiddleware` 已建立服务端匿名浏览器身份。其90天cookie期限不是科研证据有效期。浏览器 owner 字段仍不可信。

## 方案与取舍

采用现有 Agent SQLite 的 run metadata 承载有界引用记录，新增专用的领域契约和归属/CAS读写边界；不修改表结构。只存真实已验证的候选、来源和显示引用，不存新的全量聊天历史。

没有选择另外建“全局长期记忆”：会增加隐私、清理和跨会话授权面。也不选只放 WebSocket 内存：无法满足用户选择的刷新/重启恢复。若实现证明现有 metadata 无法满足事务或界限要求，应停下说明证据并另行设计，不能默默增加数据库表。

## 权威对象与不变量

一个展示快照必须包含：

- 协议 schema_version、服务端生成的 presentation_id、source_trace_id。
- 不可变 revision（规范化内容摘要，与 CandidateSet.version 分开）。
- created_at、固定 expires_at=created_at+86400；读取、刷新、确认和重放不续期。
- ordered_candidates：有序的来源观察标识、candidate_id、已验证 canonical_smiles、验证与生成 provenance。使用“来源观察+candidate_id”定位，避免跨集合 ID 碰撞。
- 已确认靶点、必要来源/证据引用、warnings，以及来源 run/tool 状态；未确认靶点不自动补猜。
- 服务端从可信上下文绑定归属，浏览器返回值不得改变归属、科学内容或证据。

每个快照至多32个实际展示候选；每个run至多8个快照，整个保留字段序列化后至多512 KiB；超限明确说明无法保留引用，不截掉后仍声称完整。只接受 succeeded/partial 中实际有效、证据被接受的候选；failed/rejected/cancelled 不发布可引用快照。partial 的 warnings/失败状态继续展示，不升级为成功。

摘要用于发现损坏和版本冲突，不当作鉴权签名。信任边界仍是受控服务端数据库与已验证会话；不声称能防止恶意数据库管理员改写。

## 展示顺序与确认

1. 服务器从现有通过校验的候选观察构建待展示清单；确定性执行与前端一致的筛选、去重、数量限制，保留来源映射。既有校验不能旁路。
2. 扩展候选传输为向后兼容的可选 reference 元信息，现有不含 reference 的 payload 仍可显示，但不能用于跨轮引用。调整前端严格字段校验，禁止任意未知字段和伪造科学内容。
3. 前端完成实际卡片渲染后，回报 presentation_id、revision 和实际展示 ID 顺序。服务端必须将其与自身预期清单严格比较；不能接受浏览器任意删改、增添或排序后直接称为权威顺序。
4. 确认成功才成为可引用视图。未发出/未显示、协议拒绝、渲染异常、确认失败不能被“第三个”自动使用；科学结果可继续显示，但提示暂不支持续接。
5. 排序或候选内容改变产生新不可变视图及 revision；旧视图仍按原所见顺序解析。请求引用的版本与当前视图冲突时澄清，不悄悄改指向。
6. 同一次回复有多个独立集合且自然语言指代不明确时，让用户选择集合或卡片；不猜“第三个”属于哪个集合。

## 浏览器与恢复

- 浏览器仅在当前标签页的 sessionStorage 保存最后确认的 trace/presentation/revision 标识，不保存 SMILES、完整回答、密钥或 owner。存储不可用时当前连接仍可显示结果，并明确无法自动恢复引用。
- 刷新/断线重新连接后，用该标识向服务端读取同一视图；服务重启后从现有SQLite读取。必须重新验证归属、24小时有效期、完整性和来源状态，成功后再恢复卡片/选择。
- 同一浏览器多个标签页各有自己的视图标识，不使用“这个用户最后一个run”替换所有标签页。新标签页、清空浏览器数据、换会话cookie或丢失标识时要求重新选择，不默认跨会话检索。
- 用户可明确清除当前选择；清除不删除来源科研任务/历史。到期记录不可解析；专用写操作中有界清理该run的到期引用元数据，不删除checkpoint或artifact。
- 24小时是引用可用期，不宣称历史科学运行记录24小时后也会被物理删除。无后续访问的过期元数据仍可保留在原run中但不可使用；全库数据保留策略不在T09内。

## 存储与权限边界

在 `src/agent/persistence/base.py` / `sqlite_store.py` 增加专用写入、确认和读取接口，复用连接/事务/锁与现有异常传播。保留字段命名空间由专用接口写入，普通 metadata 更新不得覆盖或破坏该字段；现有 decision_continuation 同样保持原有保护。

写入和确认以 BEGIN IMMEDIATE 完成归属检查、来源状态/版本检查和CAS；提交异常不报告成功。重复相同确认幂等，竞争版本拒绝。拒绝不存在、无归属、归属不匹配和结构损坏的run。读取同样要求可信session，不能直接暴露 `get_run(trace_id)` 作为浏览器接口。

元数据不能从日志或客户端输入重建科学事实。保存前沿用保密检查、JSON界限和候选验证；如果脱敏会改变身份/SMILES/摘要，应拒绝发布引用，不存损坏快照。已有状态/检查点发生改变导致原证据不再适用时，拒绝复用。

## Web 与 Agent 接线

- 在现有 `/api/agent/workflows/` 受会话中间件保护的域下注册小型科研引用读取/确认路由；保留源URL和旧响应。来源身份仅取 request.scope / websocket.scope。失败不泄露其他会话对象是否存在。
- 用独立 Web 引用服务/纯函数模块处理展示投影和协议，不向 ChatHandler 增加另一套执行循环。注入应用已持有的 Agent store，不每请求构造数据库或模型。
- 下一轮 `chat` 可带可选 reference 标识和选中 candidate_id/ordinal；这些都是待验证的选择提示。没有显式选中卡片时，只解析有界明确指代，如“刚才第三个分子”；范围/多义/越界时澄清。
- 解析后的结构化分子对象通过服务端可信参数交给 Supervisor/AgentContext，再由 Planner 绑定到实际工具输入。不得让主模型补 SMILES，也不得仅把来源放进 prompt 却仍给工具原始模糊 query。
- 普通聊天不因存在上一轮引用而自动调用工具。明确新SMILES、新靶点或清除选择必须优先处理，不偷偷复用旧结果。
- 修改靶点可复用仍有效的分子结构，但旧靶点相关活性/docking证据不得沿用。需要用户确认或新工具执行；不得将旧能量、pIC50标成新靶点结果。
- 新轮执行继续使用现有 Router/Planner/Compiler/Session、输入校验与工具权限。关闭科研工具时不因引用而绕过开关。分子生成仍仅使用既有本地生成模型。
- 重复提交用服务端归属、确认视图版本、选择与请求内容构造有界幂等身份，复用现有幂等机制；改变任一输入不能误命中旧结果。

## 拟定文件职责

- `src/agent/contracts/`：引用与不可变视图契约，复用CandidateRecord/已有provenance，不定义平行分子科学模型。
- `src/agent/persistence/`：有界、归属绑定、事务化保存/读取/确认；无新表。
- `src/web/scientific_references.py` 与独立路由模块：投影、确认、恢复与错误映射；名称为新文件建议，不当成已存在API。
- `src/web/chat_handler.py`、`src/web/app.py`、`src/agent/supervisor.py` 与现有 Planner/模板：薄接线与可信输入绑定，不重构不相关部分。
- `src/web/static/js/home/molecule_candidates.js`、main.js：传输元信息、实际显示确认、标签页引用与恢复；安全DOM契约不变。
- Python/Node回归按上述边界覆盖，最终以实际两轮聊天/WebSocket及工厂接线验证闭环。
